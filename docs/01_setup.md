# 01 — Lab Setup Guide

## VirtualBox Network Configuration

Use a **Host-Only network** so VMs can communicate with each other and with your host, but are isolated from the internet.

1. VirtualBox → File → Host Network Manager → Create → `192.168.56.0/24`
2. Assign each VM a Host-Only adapter in addition to NAT (for internet access during install)

| VM | OS | Role | IP |
|---|---|---|---|
| wazuh-manager | Ubuntu Server 22.04 | Wazuh Manager + Indexer + Dashboard | 192.168.56.10 |
| linux-agent | Ubuntu 22.04 Desktop | Linux endpoint | 192.168.56.20 |
| windows-agent | Windows 10 | Windows endpoint | 192.168.56.30 |

---

## 1 — Install Wazuh Manager (All-in-one)

SSH into `wazuh-manager` and run:

```bash
curl -sO https://packages.wazuh.com/4.10/wazuh-install.sh
sudo bash ./wazuh-install.sh -a
```

This installs Wazuh Manager, Indexer, and Dashboard in one command (~10 min).

At the end, note the output:
```
INFO: --- Summary ---
INFO: You can access the web interface https://<wazuh-manager-ip>
    User: admin
    Password: <auto-generated-password>
```

Access the dashboard at `https://192.168.56.10` and log in.

---

## 2 — Apply Manager Configuration

```bash
sudo cp configs/manager/ossec.conf /var/ossec/etc/ossec.conf
sudo /var/ossec/bin/wazuh-logtest   # verify no XML errors
sudo systemctl restart wazuh-manager
```

---

## 3 — Install Linux Agent

On the `linux-agent` VM:

```bash
# Add Wazuh repository
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH | \
  sudo gpg --no-default-keyring \
  --keyring gnupg-ring:/usr/share/keyrings/wazuh.gpg \
  --import

echo "deb [signed-by=/usr/share/keyrings/wazuh.gpg] \
  https://packages.wazuh.com/4.x/apt/ stable main" | \
  sudo tee /etc/apt/sources.list.d/wazuh.list

sudo apt-get update
sudo apt-get install -y wazuh-agent

# Enroll with manager
sudo WAZUH_MANAGER="192.168.56.10" \
     WAZUH_AGENT_NAME="linux-agent" \
     /var/ossec/bin/agent-auth -m 192.168.56.10

# Apply config from this repo
sudo cp configs/agents/linux/ossec.conf /var/ossec/etc/ossec.conf

# Enable and start
sudo systemctl enable wazuh-agent
sudo systemctl start wazuh-agent
```

Verify the agent appears in the dashboard under **Agents**.

---

## 4 — Install Windows Agent

On the `windows-agent` VM (run PowerShell as Administrator):

```powershell
# Download installer
Invoke-WebRequest -Uri https://packages.wazuh.com/4.x/windows/wazuh-agent-4.10.0-1.msi `
  -OutFile wazuh-agent.msi

# Install and enroll
msiexec /i wazuh-agent.msi `
  WAZUH_MANAGER="192.168.56.10" `
  WAZUH_AGENT_NAME="windows-agent" `
  /qn

# Start service
Start-Service -Name wazuh
```

Then copy `configs/agents/windows/ossec.conf` to  
`C:\Program Files (x86)\ossec-agent\ossec.conf` and restart the service.

---

## 5 — Install Custom Rules

Back on the manager:

```bash
sudo cp rules/local_rules.xml /var/ossec/etc/rules/local_rules.xml
sudo /var/ossec/bin/wazuh-logtest   # verify rules load
sudo systemctl restart wazuh-manager
```

Verify in dashboard: **Management → Rules → Search for "100001"**

---

## 6 — Enable auditd for FIM Who-Data (Linux Agent)

Who-data captures *which user/process* modified a file — essential for incident response.

```bash
sudo apt-get install -y auditd
sudo systemctl enable auditd
sudo systemctl start auditd
sudo systemctl restart wazuh-agent
```

Check the dashboard → **File Integrity Monitoring** → any alert should now show `agent.whodata`.
